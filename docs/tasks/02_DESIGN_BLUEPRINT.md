# TASK 02 - Проектирование интерфейса через UI/UX Pro Max

> **Единый процесс:** `AGENTS.md` -> `docs/WORKFLOW.md` -> `docs/spec/` -> `docs/change_scope_map.md` -> текущая задача -> релевантный код/тесты -> `docs/testing.md` -> `docs/templates/HANDOFF.md`. Модульные границы и согласование новых путей обязательны. Не повторяй уже пройденные проверки без новой регрессии; выполни все обязательные для текущего gate проверки, а недоступные явно пометь.


**Приоритет:** P1. **Зависимости:** TASK 00 и 01, локально установленный скилл. **Блок:** проектирование визуальной системы, **без написания компонентов и CSS**.

## Контекст

Изучи `docs/spec/UX_BRIEF.md`, `docs/spec/REQUIREMENTS.md`, `docs/spec/SKILL_SETUP.md`, текущее устройство app/ и отчет модели. Здесь решается, как экран будет выглядеть и что увидит пользователь в ошибочных состояниях. Не меняй доменные правила и контракты.

## Обязательное использование скилла

1. Проверить, что UI/UX Pro Max реально доступен в Codex (локальный SKILL.md, каталог скриптов или другая документированная установка). Открыть и прочитать локальный SKILL.md.
2. Запустить доступные **по фактической установленной версии** команды поиска дизайн-системы, UX-паттернов ошибок формы и рекомендаций для React. Примеры находятся в `docs/spec/SKILL_SETUP.md`. При отсутствии рабочей установки **остановиться с blocker**, не выдавать придуманные рекомендации за вывод скилла.
3. Отобрать рекомендации под checkout c **1-4 участниками**, а не под лендинг или маркетплейс. Отвергнуть декоративные решения, снижающие читаемость/скорость и вводящие ненужные зависимости.
4. Сформировать `app/docs/UI_SYSTEM.md` с короткой, реализуемой спецификацией: цветовые токены (HEX или CSS variables), типографика, шкала отступов, радиусы/тени, контейнер desktop, перестройка на 360 px, карточка участника, форма и ошибки, сводка, review, pending, success, sold-out.
5. Включить состояния: пустой возраст и незавершенный итог; ошибка ребенка без взрослого; удаление одного из нескольких участников; четвертый участник; длинное имя; loading; техническая ошибка; фокус с клавиатуры.
6. Сформировать `app/docs/SKILL_USAGE.md`: реально открытый локальный путь, запросы к скиллу, принятые и отклоненные советы. Достаточно 8-15 осмысленных строк, не создавать энциклопедию.
7. Сформулировать короткую памятку для реализации разметки (порядок блоков и семантика) и для CSS (конкретные значения) в одном документе UI_SYSTEM.md.

## Запрещено

Не писать JSX/CSS, не генерировать картинку или логотип, не добавлять Tailwind, shadcn, икон-пакеты, сторонние шрифты, дополнительные Skills и анимационные библиотеки. Не менять `app/package.json`, `app/src/`*, bookingModel.ts и тесты. Не исполнять установку скилла самостоятельно без явного согласования.

## Gate

- Локальный SKILL.md действительно прочитан, рекомендации получены не из памяти.
- Есть два файла: `app/docs/UI_SYSTEM.md` и `app/docs/SKILL_USAGE.md`.
- Можно реализовать дизайн **без дополнительного обсуждения** цвета, отступов, адаптивных размеров и состояний.
- 360 px и наличие нескольких карточек покрыты отдельным макетным сценарием на уровне описания (без ложного утверждения о браузерном тесте).
- Код приложения и тесты не изменены; при чисто документарной правке не нужно повторно запускать тесты и build (уровень 0 `docs/testing.md` ).

## Отчет

Указать точные команды/фактические результаты скилла, конкретные принятые дизайн-решения, сомнения и нерешенные вопросы. Gate не проходит, если скилл не запущен.
