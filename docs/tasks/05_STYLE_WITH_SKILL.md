## Обязательное использование скилла

1. Прочитай `docs/spec/SKILL_SETUP.md`, локальный `app/.agents/skills/ui-ux-pro-max/SKILL.md` (либо фактически установленный путь) и `app/docs/UI_SYSTEM.md`.
2. Реально вызови/используй UI/UX Pro Max для review конкретного интерфейса: динамические формы, валидация, error messaging, responsive 360 px, визуальная иерархия цены. Примеры команд в `docs/spec/SKILL_SETUP.md`; **путь и аргументы уточнить по локальному SKILL.md**.
3. Зафиксируй новые принятые/отклоненные рекомендации в `app/docs/SKILL_USAGE.md`. Если инструмент отсутствует, сообщи blocker, не имитируй его применение.

## Стилизация

- Привести `app/src/styles.css` к конкретным токенам из `app/docs/UI_SYSTEM.md`: основные цвета, фон, тексты, границы, шрифты, отступы, тени, радиусы, интерактивные состояния.
- Desktop: максимальная ширина 960-1100 px и понятная двухколоночная иерархия формы и сводки. Не разрывать смысловой порядок Tab ради сетки.
- 360 px: одна колонка, поля по ширине контента, около 16 px горизонтальных отступов, сводка перед CTA, без sticky-панелей, перекрывающих клавиатуру. Предусмотреть min-width: 0 у вложенных grid/flex блоков, длинные email/имена, внутренние отступы.
- Компоненты: поле имени, возраст, блок участника и удаление, Добавить, тарифные подсказки, сводка, review, pending, success, sold-out, error/retry. У всех состояний одна система отступов и типографики.
- Ошибки отображать у конкретного поля; ошибку сопровождения возле группы, с заметным, но спокойным стилем. Не передавать важное состояние только цветом.
- Фокус должен быть видимым при Tab. Связать label/aria-describedby/aria-invalid; на смене экрана фокус на заголовке, на первой ошибке - на соответствующем контроле. При удалении участника не терять видимый фокус.
- Никаких анимаций, если они не решают задачу. Не использовать платные ассеты или скачанные случайные картинки.

## Границы изменений

Можно менять **только** `app/src/styles.css`, JSX-разметку/классы в BookingForm.tsx, BookingSummary.tsx, BookingReview.tsx, BookingResult.tsx, App.tsx в пределах презентационного слоя, `app/docs/SKILL_USAGE.md` и уточнение `app/docs/UI_SYSTEM.md`. Запрещено менять тарифы, парсер возраста, валидацию, сервис, типы, state transitions или тесты ради CSS. Не подключать Tailwind, shadcn, Radix, Google Fonts, икон-пакеты без согласования.

## Контроль качества

- Desktop: структура выглядит завершенной, главная кнопка заметна, тарифы понятны, сводка читаема.
- Viewport **360 px**: нет горизонтальной прокрутки, карточки не обрезаны, кнопка удаления и суммы не наезжают друг на друга, CTA доступна с открытой экранной клавиатурой.
- Проверить U11, U12, U14, U16, U17; keyboard-only проход по editing -> review -> confirm -> result.
- Если нет браузера, не отмечать визуальные критерии пройденными. Описать действия для ручного контроля.
- Поведение U01-U10 не должно меняться: прогнать релевантный UI smoke при правках разметки/фокуса. `npm run build` после TSX-изменений; полный unit-набор без изменения модели не повторять.
