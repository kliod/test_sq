## Автоматические проверки

Проверить S01-S03 из `docs/spec/ACCEPTANCE.md`: Redux Toolkit действительно управляет сценарием, reducer соблюдает переходы, интеграционные тесты используют Provider и отдельный store без дублирования RHF-черновика. Включить `bookingSlice.test.ts` в финальный запуск тестов.

Пути тестов: `app/src/pages/booking/model/{bookingModel,bookingSlice}.test.ts`, `app/src/app/store/bookingIntegration.test.tsx`. Последний проверяет сборку Provider/store/`App`/`BookingPage` и сервис через SSR; для кликов, сохранения RHF и guard требуется отдельная проверка с DOM или браузером. Тесты верхнего слоя импортируют booking через его публичный API, тесты слайса не импортируют `app`.

1. npm run test для M01-M16. Исправить реальные ошибки модели/тестов, не ослаблять ожидания ради зеленого результата.
2. `npm run build` с чистым TypeScript/Vite. Устранить любые реальные ошибки сборки.
3. Добавить минимальную интеграционную проверку критичных U03/U04 с подставным BookingService, **если это можно сделать надежно**. При необходимости допустима React Testing Library + user-event как **одна оправданная тестовая зависимость**; не тянуть Playwright ради одного теста. Счетчик должен удостоверять ровно один confirm при быстрой повторной активации. Если тест недоступен в среде, явно перенести риск в отчет и описать ручную проверку.
4. Запустить демо-режимы обычного URL и ?scenario=sold-out; не использовать случайные исходы и скрытые кнопки, не добавлять отдельный роутер.

## Ручной smoke (в реальном браузере)

- **Успех:** начать заказ, заполнить 13+18, увидеть 3 000 руб., сделать review, вернуться, отредактировать, заново проверить, подтвердить и увидеть условный номер.
- **Отказ:** с query scenario=sold-out повторить путь, убедиться, что отказ возникает после confirm, номера нет, данные сохраняются, кнопки изменения и повтора работают.
- **Ошибки:** 13+17, пустой/дробный/отрицательный возраст, пробельное имя, невалидный email, пятый участник, удаление среднего, Enter в email.
- **Мобильность:** DevTools ширина 360 px, viewport с виртуальной клавиатурой если доступен, длинные имена, все блоки и CTA, отсутствие overflow.
- **Доступность:** только клавиатура, порядок Tab, видимый focus, ясное сообщение об ошибке у поля/группы и заголовок после переходов.
- **Сеть/гонки:** быстро двойное подтверждение, задержка и технический reject через тестовый сервис (не выдавать его за режим sold-out).

Если Codex не имеет доступа к GUI браузера, составить чек-лист для человека и честно отметить непроверенные U-пункты. Не выдавать `npm run build` за браузерный тест.
