## Компоненты и ответственность

1. `app/src/app/App.tsx`: единственный useForm<BookingFormValues> с shouldUnregister:false; useFieldArray для participants на постоянно смонтированном уровне. Шаги editing / review и **только нормализованный** reviewedBooking хранить в `bookingSlice.ts` (Redux Toolkit); читать через типизированные селекторы, переходить через actions. Не заводить второй mutable draft или локальную копию состояния сценария.
2. `app/src/pages/booking/ui/BookingForm.tsx`: поля имени и возраста для 1-4 участников, общий email, добавление/удаление; все type="button" для вспомогательных кнопок. Ключи карточек по field.id, не по индексу. Внешний массив RHF индексируется для register, но React key стабилен.
3. `app/src/pages/booking/ui/BookingSummary.tsx`: вычисляемая сводка из наблюдаемых значений editing **или** из нормализованного Booking на review. Не хранить сумму в useState; не считать пустой возраст нулем; не выдавать частичную сумму за итог. Если все возраста корректны, показывать тарифы и сумму, даже если правило сопровождения еще нарушено.
4. `app/src/pages/booking/ui/BookingReview.tsx`: **только чтение** снимка reviewedBooking с email, именами, возрастами, категориями и ценами, Изменить возвращает в editing без сброса полей. Кнопку confirm пока держать явно отключенной/неактивной с сообщением о незавершенном шаге TASK 04, а не симулировать успех.

`app/src/pages/booking/ui/BookingPage.tsx` собирает представление текущего шага из props. `App` использует typed hooks и корневой селектор из `app/src/app/store/selectors.ts`; форма и guard остаются в `App`. Внешние импорты сценария идут через `app/src/pages/booking/index.ts`, слайс не импортирует `app` даже ради `RootState` или тестов.

## Поведение и ошибки

- При Проверить заказ вызвать чистую validateAndNormalize(getValues()). При ошибке связать сообщения с конкретными полями и общим блоком группы. Не делать переход к review, переместить фокус на первую ошибку.
- При успехе создать **новый** объект снимка Booking и перейти в review; перевести фокус на заголовок экрана.
- При возврате к редактированию поля остаются в RHF; после нового продолжения снимок пересоздается.
- Начальный массив из одного участника; убрать последнего нельзя; после четвертого Добавить недоступно.
- Поле возраста должно допускать ввод промежуточного пустого значения, чтобы пользователь мог удалить старый возраст. Оптимально обычное поле с inputMode="numeric", хранение строки, без автоматического приведения числа по onChange.
- Не терять фокус при удалении карточки: перенести на ближайшее существующее поле или кнопку добавления.
- Enter в поле ввода активирует проверку формы, **не** mock-confirm.
- Нужны семантические label, aria-describedby, aria-invalid и понятное сообщение о группе.

## Проверки и gate

- U01: три участника, удалить среднего - значения других полей сохранены.
- U02: review -> Изменить -> поменять 13 на 14 -> новый review и цена корректны.
- S01/S02 из приемки: Redux владеет сценарием; reducer проверен на переходы editing/review и очистку старого снимка при возврате.
- U14: пустой/невалидный возраст не дает ложного итога.
- U15: Enter на форме не вызывает никакого confirm.
- U16: 13+17 блокируется понятной ошибкой; 13+18 проходит на review.
- На четвертом добавление отключено, на одном удаление не допускается.
- После изменений TSX проходит `npm run build`. Успешный доменный набор TASK 01 не повторять без изменений модели; если браузер не открывался, U-сценарии маркируются как непроверенные.
