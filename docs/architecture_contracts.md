# Контракты и границы архитектуры SQOCH

Полные типы и состояния - в `docs/spec/CONTRACTS.md`; этот документ **не дублирует контракт**.

- **Источник истины для бизнес-правил:** `docs/spec/REQUIREMENTS.md` и чистая модель `bookingModel.ts` после реализации. Компоненты не вправе независимо пересчитывать категории и придумывать ограничения возраста.
- **Редактируемый draft:** одно состояние React Hook Form на постоянно смонтированном уровне `App.tsx`; `useFieldArray` дает стабильные ключи. Второй mutable draft запрещен.
- **Состояние сценария:** Redux Toolkit slice — единственный владелец шага, нормализованного снимка, технической ошибки и номера результата. Store, типизированные hooks и Provider связывают его с React. RHF-черновик и вычисляемая цена не копируются в Redux; `inFlightRef` принадлежит `App`. Подробности и допустимые переходы — `docs/spec/CONTRACTS.md`.
- **Review snapshot:** нормализованный Booking, созданный из валидной формы. UI на review читает снимок, перед confirm повторная валидация `getValues()` и сверка с ним. Позднее/устаревшее изменение не создает другой payload молча.
- **Результат confirm:** только `BookingService` определяет `success|soldOut`; `Promise.reject` означает техническую ошибку. Сообщения внешней границы не должны обходить валидацию модели.
- **Повторы:** `inFlightRef.current` выставляется синхронно, пока запрос выполняется; UI дополнительно блокирует управление. Демо не претендует на серверную идемпотентность или реальную бронь.
- **Тестируемость:** при необходимости внедряй mock service через небольшой prop/factory/DI seam; не строй приложение вокруг абстракции для гипотетических провайдеров.
- **Внешняя граница:** нет сети и настоящей БД; не добавляй создание API, миграций, persistence/replay и мониторинга ради общего шаблона.
- **Версии и совместимость:** при изменении types/schema укажи, какие функции и компоненты являются потребителями. Не дублируй типы в представлении.
- **Приватность:** email существует в памяти формы и mock payload; не логируй реальные адреса и не сохраняй в localStorage. Демо-номер заказа не означает оплату.

Сначала меняй владеющий контракт с явным согласием, затем потребителей; никогда не исправляй ошибку контракта параллельной схемой в UI.
