# UI/UX-бриф для UI/UX Pro Max

## Задача

Нужен компактный, выразительный, но утилитарный checkout покупки билетов на вымышленное мероприятие. Это самостоятельный React SPA с моковым confirm, а не лендинг, CRM, афиша или интернет-магазин. Пользователь оформляет заказ на 1-4 участников, вводит их имена и возраста, один email, видит цены и итоги, проверяет заказ и получает успех либо отказ из-за отсутствия мест.

## Страницы и состояние

1. **Editing**: заголовок мероприятия, краткие тарифы, правило сопровождения, от одной до четырех повторяемых карточек участника, email, сводка и CTA `Проверить заказ`. Поля и цены обновляются в процессе ввода.
2. **Review + submitting**: неизменяемый снимок, список людей с возрастами, категорий и цен, общая сумма, email, `Изменить`/`Подтвердить заказ`; при отправке ожидание и блокировка действий.
3. **Result**: общий компонент с альтернативным содержимым для `success` и `soldOut`. Sold-out не обещает освобождение мест при правке возраста; есть повторить и изменить данные.

## Ограничения и иерархия

- Desktop: аккуратная двухколоночная компоновка формы и сводки, общая максимальная ширина около 960-1100 px.
- Mobile **360 px**: одна колонка, внешние отступы около 16 px, сводка перед основной кнопкой, никакой панели поверх полей, никакого горизонтального скролла.
- Визуальный приоритет: мероприятие -> участники -> контакт -> итог -> действие. Ошибки прямо у проблемного элемента или группы.
- Отображать полный/детский тариф и автоматический перерасчет. На пустом или некорректном возрасте **не показывать неполную сумму как окончательный итог**.
- Одна акцентная палитра, остальное нейтральное. Читаемые 14-16 px подписи, видимые состояния фокуса, минимум декоративных эффектов. Различать успех, отказ и техническую ошибку.
- Поля хорошо работают с Tab/Enter. У ошибок есть подписанные связи, фокус после переходов управляется предсказуемо.
- Нет обязательных картинок, платных шрифтов, икон-пакетов, сложных переходов, анимаций и маркетинговых секций.
- Текст интерфейса на русском. Не писать про реальную оплату, отправленные билеты и занятые места до момента confirm.

## Выбор технического оформления

React + TypeScript; Redux Toolkit + React Redux для состояния сценария, React Hook Form для ввода без копии черновика в store, обычный CSS и CSS custom properties. Дизайн-скилл должен дать **конкретный** набор переменных, типографику, отступы, геометрию и состояния элементов, но не тянуть Tailwind, shadcn/ui, Radix, анимационные библиотеки или маршрутизатор. Не копировать вывод скилла вслепую. Принять решения для формы, а не для абстрактного биллинга.
