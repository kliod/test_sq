# Этапы разработки SQOCH

Этап определяется наблюдаемым результатом, а не количеством созданных файлов. Рабочая последовательность фиксирована задачами `docs/tasks/00...06`. Универсальные «реальная backend-интеграция», «эксплуатационная готовность» и «оценка LLM» к этому тестовому SPA **не применяются**.

| Stage | Задачи | Что считается готовым |
|---|---|---|
| 0: границы известны | 00 | `AGENTS.md`, `docs/spec/**`, `docs/change_scope_map.md` прочитаны; минимальный Vite-проект запускается |
| 1: логика и дизайн-контракт | 01, 02 | Доменные M01-M16 пройдены; реальный UI/UX Pro Max сформировал `UI_SYSTEM.md` |
| 2: сквозной сценарий | 03, 04 | Пользователь реально проходит editing -> review -> success или soldOut; ошибки/guard определены |
| 3: адаптивность и устойчивость | 05 | Два результата, ошибки и 360 px доступны, клавиатура и фокус проверены где возможно |
| 4: доказательства и поставка | 06 | Контроль приемки, сборка, README, фактическое время и видео с подтверждением человека |

Выполнять одним агентом последовательно. Несколько агентов допустимы только при действительно непересекающихся файлах и зафиксированном контракте. Все необходимое для данного тестового задания можно выполнить без многоагентности.
