# SQOCH — оформление билетов

Тестовое задание: адаптивное React-приложение для оформления билетов на вымышленное мероприятие «Вечер открытий».

Пользователь заполняет данные участников и контактный email, проверяет состав и стоимость заказа, при необходимости возвращается к редактированию и подтверждает заказ. Подтверждение завершается успехом или сообщением об отсутствии мест.

## Быстрый запуск

Использованное окружение: **Node.js 24.15.0, npm 11.12.1**.

```sh
cd app
npm ci
npm run dev -- --host 127.0.0.1 --port 5175 --strictPort
```

После запуска доступны два воспроизводимых сценария:

- [Успешное оформление](http://127.0.0.1:5175/) — после подтверждения появится условный номер `DEMO-001`.
- [Отсутствие мест](http://127.0.0.1:5175/?scenario=sold-out) — отказ появится после подтверждения. Можно изменить данные или повторить попытку.

Если порт 5175 занят, укажите свободный порт в команде и адресе браузера.

## Правила оформления

- В заказе от 1 до 4 участников, у каждого обязательны имя и возраст. Контактный email общий для заказа.
- До 14 лет билет стоит **1 000 руб.**, с 14 лет — **2 000 руб.**
- Если есть ребенок младше 14 лет, в том же заказе должен быть участник от 18 лет.
- Стоимость обновляется при изменении возраста. Невалидный или незаполненный возраст не дает показать неполную сумму как окончательный итог.
- На шаге проверки видны участники, тарифы, итог и email. Возврат к редактированию и отказ сохраняют введенные данные.
- Во время подтверждения действия заблокированы; повторная активация не создает второй запрос в рамках той же попытки.

Интерфейс рассчитан на desktop и мобильный экран шириной 360 px. Есть связанные с полями ошибки, видимый фокус и управление с клавиатуры.

## Стек и архитектура

**React, TypeScript, Vite, Redux Toolkit, React Redux, React Hook Form, CSS, Vitest.**

Исходники находятся в `app/src/`:

- `app/` — сборка приложения, Provider, store и координация сценария. React Hook Form владеет редактируемой формой; Redux хранит шаг, проверенный снимок заказа и результат подтверждения.
- `pages/booking/model/` — чистые функции валидации, нормализации, расчета стоимости и сравнения снимков, а также reducer переходов.
- `pages/booking/api/` — контракт сервиса и асинхронный mock подтверждения.
- `pages/booking/ui/` — форма участников, сводка, проверка заказа и экраны результата.

Перед подтверждением форма повторно валидируется и сравнивается со снимком, показанным на шаге проверки. Стоимость вычисляется из данных участников и отдельно в store не хранится. Техническая ошибка запроса обрабатывается отдельно от отсутствия мест и допускает повтор.

## Проверки и сборка

Из папки `app/`:

```sh
npm run test
npm run build
```

**31 тест:** 16 проверок доменной модели, 10 проверок reducer и 5 интеграционных SSR-проверок. Тесты и сборка прошли. SSR-проверки не заменяют проверку пользовательских действий в браузере; success, sold-out, редактирование, ошибки, клавиатура и ширина 360 px проверены отдельно.

Сборка находится в `app/dist/`. Для локального просмотра:

```sh
npm exec vite preview -- --host 127.0.0.1 --port 4173 --strictPort
```

## Демо и время разработки

[Короткое демо — 53 секунды](app/sqoch-demo.mp4): заказ 13 + 18 лет с итогом 3 000 руб., проверка и редактирование, успешное подтверждение, отсутствие мест с повторной попыткой и мобильный интерфейс 360 px. Видео без звука, с подписями.

Фактическое время разработки — **1 час 05 минут**.

## Ограничения

Это демонстрация на моковых данных. Сервис отвечает через 600 мс; исход определяется URL. Оплата, реальное бронирование, отправка билетов и email не выполняются. Backend и постоянного хранения нет: обновление страницы сбрасывает заказ. Номер `DEMO-001` условный и не уникальный.
