# SQOCH — входные инструкции для Codex

Подробные правила проекта находятся в [docs/WORKFLOW.md](docs/WORKFLOW.md). Прочитай их до выполнения задач и правок. Пути в документации считаются от корня SQOCH, если явно не указано иначе.

## Память

- Используй kaeru как единственное долговременное хранилище фактов, решений, задач, гипотез, результатов и handoff. Не создавай параллельную локальную память; встроенная память может содержать только указатели на kaeru.
- В начале сессии вызови `initiatives`, выбери инициативу `sqoch` и вызови `context`; для структурного обзора используй `view="map"`. Не считай инициативу другого проекта инициативой SQOCH без подтверждающих данных.
- Для обычных проектных вызовов передавай `initiative`; в kaeru 0.8 поиск использует `initiatives` (список) и `text`. Для полных записей используй `read`, для предыдущих версий — `history`. Сохраняй сведения через `note`, `reference`, `task` или `claim`.
- Если инструменты kaeru недоступны как вызываемые инструменты, не трать время на их поиск. Используй Node REPL fetch и локальный MCP `http://127.0.0.1:9876/mcp`: POST `initialize` с заголовками `Content-Type: application/json` и `Accept: application/json, text/event-stream`; сохрани заголовок ответа `mcp-session-id`; POST `notifications/initialized` с `Mcp-Session-Id`; затем `tools/call` для `initiatives` и `context` выбранной инициативы. При устаревшем каталоге вызови `tools/list` в той же сессии. Для этого SSE-потока предпочитай Node fetch вместо PowerShell Invoke-WebRequest/curl.

## Вход в работу

1. Прочитай [docs/WORKFLOW.md](docs/WORKFLOW.md) и указанные там документы текущей задачи. Навигация — [docs/README.md](docs/README.md).
2. Источник требований — `docs/spec/`; задачи выполняются последовательно `docs/tasks/00…06`.
3. Приложение создается в `app/`. До первых изменений приложения напомни пользователю включить запись процесса. Установку зависимостей согласуй по текущей задаче.
